How to use these labs

  • Day 1 was about your own effectiveness. Day 2 is about industrializing: agents on complex tasks, team conventions, automation, and a common stack.
  • You start from a clean reference state (pulselab_day2_starter.zip), so an unfinished Day 1 lab does not matter.
  • Same conventions as Day 1: modes instead of products (see table), dashed boxes for prompts you write yourself, ticks saved in your browser, an AI journal at the bottom.
  • One branch per lab, starting from main. main stays clean.
Safety rules unchanged: no secrets, no confidential data, no unpublished results in prompts. Agents get the minimum permissions; keep approvals on for shell commands; read every diff.

TP 2.1 · Large-scale refactoring with an agent

Learning goals
  • Run a multi-file refactoring with plan, increments, guardrails and verification.
  • Detect an agent that weakens tests or drifts out of scope.

Target design. (1) a frozen dataclass Config replaces the global CONFIG dict; (2) a Run dataclass replaces the run dict; (3) pathlib.Path replaces os.path and glob; (4) logging replaces print for messages (the results table printed by print_table stays a print); (5) type hints on the public functions.

Invariants. The summary CSV and the detected pulses do not change (tests/golden/* must be untouched); the command-line interface does not change; no new dependency.

TP 2.2 · Advanced tests: mutation score, edge cases, properties

Learning goals
  • Measure test strength, not only coverage.
  • Use AI to target surviving mutants, then judge which survivors are real gaps and which are equivalent.
  • Write property-based tests for numerical code.

scripts/mini_mutation.py applies 12 small changes (mutants) to a copy of the code, one at a time, and runs your tests. A mutant that the tests do not detect survives: your tests did not notice that change.

terminal
git switch main
git switch -c tests-adv
python scripts/mini_mutation.py
2.2.1Baseline: mutation score and coverageHUMAN4 min
  • Run the script (under a minute: about 45 s on the trainer machine). Write down the score and the surviving mutants. Also run the coverage command.
Check before you move on
  • Baseline score: ___ / 12. Survivors: ___ (expected: about 7 / 12 killed, 5 survivors).
2.2.2Ask for a test plan aimed at the survivorsPLANCHAT5 min
  • Give the assistant the list of survivors and the source lines. For each survivor it must either propose a test that kills it, or argue that it is an equivalent mutant (the change does not alter behaviour).
  • Do not accept an 'equivalent' claim without checking it yourself.
Your prompt: write it yourself, fill the blanks
GOAL:         [kill the surviving mutants, or prove they are equivalent]
CONTEXT:      [the survivors printed by mini_mutation.py and the source lines they change]
CONSTRAINTS:  [tests only, do not modify the source; each test asserts a real value; seeded data]
FORMAT:       [table: mutant | your test idea (input, expected value) OR why it is equivalent]
VERIFICATION: [for each new test, say which mutant it kills and how I can check by hand]
2.2.3Write the tests and prove each one kills its mutantEDITAGENT10 min
  • Implement the approved tests. For at least two of them, apply the mutation by hand and check that the new test fails; then restore the code.
  • Re-run python scripts/mini_mutation.py.
Check before you move on
  • Score improved. Every new test names the mutant it kills (in its docstring).
Hint 1

M3 needs a sine exactly on the lower band edge: nperseg=1000 at 1 kHz gives bins exactly 1 Hz apart, so a 50 Hz sine and the band (50, 60).

Hint 2

M9 needs a sample exactly equal to the threshold.

Hint 3

M4 needs a call with fmin == fmax.

2.2.4Property-based testsEDITAGENT8 min
  • Write the three properties below as tests. With hypothesis (if you can install it): @given(...) with a bounded number of examples. Without: a loop over 50 seeds with numpy.random.default_rng(seed).
the three properties
# Property 1: remove_offset
#   for any float array x (length >= 2): the input is not modified, the mean of the result is ~0,
#   and applying it twice gives the same result.
# Property 2: dominant_frequency
#   for any integer frequency f in [2, 200] Hz, fs = 1000 Hz, a sine of any amplitude on any offset
#   gives dominant_frequency(x, fs) == f within 0.3 Hz.
# Property 3: find_pulses
#   for any array: indices are increasing, consecutive indices differ by at least the gap,
#   every returned sample is above the threshold, and no index is the first or last sample.
  • Ask the assistant for a first version, then read the assertions and the input ranges: a property that is too weak (or a range that avoids the interesting cases) proves nothing.
Check before you move on
  • The 3 property tests pass and each runs in a few seconds.
  • You can explain what input range each one explores.
Hint 1

For hypothesis floats use bounded, finite values: st.floats(-1e3, 1e3, allow_nan=False, allow_infinity=False); arrays with hypothesis.extra.numpy.arrays.

Hint 2

A property for remove_offset should not require exact zero: use a tolerance relative to the data scale.

2.2.5Classify the remaining survivorsHUMAN3 min
  • For each mutant that still survives, write one line: missing test or equivalent mutant, with the reason.
Check before you move on
  • Your final score and a justified classification of every survivor.
Hint 1

M2: what is the value of freqs[0] in a Welch spectrum?

Hint 2

M11: what happens in curve_fit when there is a single pulse (or none), whatever the initial guess?

2.5.2Implement tools/precommit.py (one script, testable)AGENTEDIT15 min
  • A Python script (no external dependency) that runs, in this order: (1) secret scan on the staged diff (added lines only), (2) python -m compileall, (3) pytest -x -q, (4) optional AI advice.
  • AI advice: if the environment variable PULSELAB_AI_REVIEW_CMD is set, run that command with the staged diff on stdin (truncated to 20 000 characters), print its output as advice, and never fail the commit because of it: errors and a timeout (PULSELAB_AI_TIMEOUT, default 60 s) only print a warning.

S2  a test is broken (change 20*log10 to 10*log10) -> commit BLOCKED, failing test shown
S3  a staged file contains  API_KEY = "abcd1234efgh5678"  -> commit BLOCKED, the line is shown
S4  AI review command prints advice                -> advice shown, commit passes
S5  AI review command exits with an error          -> warning shown, commit passes
S6  AI review command slower than the timeout      -> warning shown, commit passes
